> **Esta é a versão 2.** A versão 1 (mesmo dia, mesma manhã) apoiou-se no ADR
> 0016, que tratava o schema `salic_bronze` como a Bronze e deixava as silvers
> lendo `source('bronze_<origem>', ...)`. A dona do projeto corrigiu a leitura
> à tarde: **o ADR 0010 pede um schema só, `salic`, com
> `bronze_<origem>_<tabela>` e `silver_<origem>_<tabela>` dentro**, e o
> `salic_bronze` deixa de existir. Esta versão substitui a anterior inteira.
> O que foi feito sob a v1 (PR #106 = ADR 0016; PR #107 = lote
> `controledeacesso`; branch local do lote `bdcorporativo`) é desfeito ou

**Objetivo:** o SALIC fica inteiro no schema `salic`: a ingestão v2 grava
`salic.bronze_<banco>_<tabela>` (Bronze, cópia fiel), e o dbt tem só
`salic/silver_<banco>_<tabela>.sql` (tipa) mais os modelos manuais. Some o
`salic_bronze`, some o `salic_dbt/`.

**Arquitetura (desenho A, confirmado pela Luiza em 2026-10-27):** não há raw
nem modelo `bronze_*.sql` para o SALIC. A Bronze é a tabela que o Trino grava,
no schema da fonte, com o prefixo `bronze_`. É o que o Mapas já faz
(`mapas.bronze_agent`, source `mapas`, `silver_agent.sql` lendo
`source("mapas", "bronze_agent")`). O SALIC segue o mesmo molde, com
`<banco>_<tabela>` como entidade (ADR 0010, R12).

**Stack:** Airflow 3.2 + Trino 478 (conector PostgreSQL, que suporta
`TRUNCATE`), dbt-core 1.10.23, Postgres `dbanalytics`.

```python
DEFAULT_BRONZE_SCHEMA = "salic"  # era "bronze"; ver ADR 0017


def bronze_table_name(database: str, table: str) -> str:
    """Nome da tabela na bronze: ``bronze_<banco>_<tabela>``, tudo em minúsculas.

    O schema de destino é a fonte (``salic``) e o nome carrega a camada e a
    entidade ``<banco>_<tabela>`` do ADR 0010 — ``bronze_sac_projetos``. Até o
    ADR 0017 era ``<banco>__<tabela>`` num schema próprio (``salic_bronze``).
    """
    return f"bronze_{database.lower()}_{table.lower()}"


def bronze_truncate(target: dict) -> str:
    """TRUNCATE da tabela bronze. Mantém a tabela (e as views que dependem dela)."""
    return f"TRUNCATE TABLE {bronze_fqtn(target)}"


def columns_match(existing: list[str], columns: list[tuple[str, str]]) -> bool:
    """A tabela existente tem exatamente as colunas que a carga vai gravar, na ordem?

    Compara nome em minúsculas; a última coluna da tabela é a técnica
    :data:`SLICE_COLUMN`. Tipo não entra: na bronze tudo é ``varchar``.
    """
    esperado = [name.lower() for name, _ in columns] + [SLICE_COLUMN]
    return [c.lower() for c in existing] == esperado
```

def _prepare_bronze_table(target: dict, columns: list[tuple[str, str]]) -> None:
    """Deixa a tabela bronze vazia e com a forma da origem.

    Se ela já existe com as mesmas colunas, TRUNCATE: a tabela fica, e com ela
    as views do dbt que a leem (silver_*). DROP só quando a forma mudou — e aí
    o Postgres recusa se houver view dependente, o que é o aviso certo: alguém
    precisa recriar a silver para a forma nova.
    """
    existentes = _existing_columns(target)
    if existentes and columns_match(existentes, columns):
        trino_run(bronze_truncate(target))
        logging.info(
            "[salic_trino] %s.%s truncada (%d coluna(s), forma igual).",
            bronze_schema(target), target["bronze_table"], len(columns),
        )
        return
    drop, create = bronze_ddl(target, columns)
    trino_run(drop)
    trino_run(create)
    logging.info(
        "[salic_trino] %s.%s %s com %d coluna(s) + %s.",
        bronze_schema(target), target["bronze_table"],
        "recriada (forma mudou)" if existentes else "criada",
        len(columns), SLICE_COLUMN,
    )

```markdown
# ADR 0017 — A Bronze do SALIC é gravada pela ingestão no schema `salic`, como `bronze_<banco>_<tabela>`

- **Data:** 2026-10-27
- **Status:** proposto
- **Escopo:** Bronze e Silver do SALIC; regra R3 do ADR 0010 para fonte sem raw
- **Substitui:** [ADR 0016](0016-salic-sem-raw-a-source-e-a-bronze.md), inteiro
- **Substitui em parte:** ADR 0010, regra transversal "Silver lê a Bronze por `ref()`"
- **Origem:** revisão do plano de migração do `salic_dbt`, no mesmo dia do 0016

## Contexto

O ADR 0010 desenha o SALIC como `salic.bronze_agentes_agentes → salic.silver_agentes_agentes`:
um schema por fonte, camada no nome. A ingestão v2 (ADR 0005) grava a cópia fiel
num schema à parte, `salic_bronze`, como `<banco>__<tabela>`, e o 0016 tinha
aceitado isso como "a Bronze". Não é o que o 0010 pede, e deixava dois schemas
para uma fonte só. O Mapas já faz do jeito certo: a DAG grava `mapas.bronze_<tabela>`
e a silver lê `source('mapas', 'bronze_<tabela>')`.

Há ainda um problema operacional: a DAG recria cada tabela com `DROP TABLE` pelo
Trino, sem `CASCADE`, e o Postgres recusa o `DROP` quando há view dependente. Em
2026-10-27 havia 589 views do dbt sobre as 589 tabelas: a carga estava bloqueada.

## Decisão

1. A Bronze do SALIC é a tabela gravada pela `salic_ingestion_trino` no schema
   `salic`, com nome `bronze_<banco>_<tabela>` (`bronze_sac_projetos`). Não há raw
   nem modelo dbt `bronze_*` para o SALIC.
2. No dbt, a source chama-se `salic` (schema `salic`) e declara essas tabelas.
   A Silver é `salic/silver_<banco>_<tabela>.sql` e lê
   `source('salic', 'bronze_<banco>_<tabela>')`.
3. Regra geral, que também vale para o Mapas: fonte sem raw tem a Bronze gravada
   pela ingestão no schema da fonte, com prefixo `bronze_`; a Silver a lê por
   `source('<fonte>', 'bronze_<entidade>')`. A R3 aceita `source()` quando o nome
   da source é o da pasta e a tabela começa com `bronze_`. Fonte com raw continua
   com modelo `bronze_*` e `ref()`.
4. A ingestão não derruba tabela cuja forma não mudou: `TRUNCATE` + `INSERT`. `DROP`
   + `CREATE` só quando a lista de colunas da origem mudou — e aí a falha por view
   dependente é o aviso de que a silver precisa ser recriada.
5. O schema `salic_bronze` é encerrado: as tabelas mudam de schema e de nome por
   `ALTER TABLE`, sem recarga.

## Por quê

Um schema por fonte é o que o 0010 decidiu e o que Ranger, OpenMetadata e o site
esperam. Bronze física gravada pela DAG, sem cópia dbt, é o único desenho que não
duplica 58 GB nem prende a carga. TRUNCATE em vez de DROP é o que permite silver
como view sobre a bronze sem quebrar a ingestão.

## O que foi descartado

- Manter `salic_bronze` como source "que é Bronze" (ADR 0016): dois schemas para
  uma fonte, fora do desenho do 0010.
- Modelo dbt `bronze_*` lendo `salic_bronze` (padrão TransfereGov): como view prende
  o DROP; como table duplica 58 GB a cada `dbt run`.
- Recarga completa para mudar o nome: ~2 h pela VPN; o rename é instantâneo.

## Consequências

- `verificar.py`: R3 aceita `source(<pasta>, bronze_*)`. Os 59 do Mapas zeram.
- `salic/bronze_sac_projetos` e `salic/bronze_sac_captacao` saem antes da ingestão
  gravar com esses nomes (colisão de relação em `prod`).
- Variable `salic_trino_bronze_schema` passa a `salic` no ambiente.
- R9 (Bronze guarda histórico) continua não cumprida: TRUNCATE apaga como o DROP
  apagava. Fora deste ADR.
```
